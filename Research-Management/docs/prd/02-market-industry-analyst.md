# PRD-02 · 行业-研究员维护

> 投研系统的主数据模块。维护"市场 → 行业 → 研究员"的从属关系，是 ⑤研报归口、④组合标的、③股票池行业维度的数据基础。

**状态**：草案 v2
**最近更新**：2026-08-17
**依赖**：① 配置页面（用户/角色/权限点）
**被依赖**：③ 股票池、④ 模拟组合、⑤ 研报上传

---

## 1. 目标与范围

- 按**市场**维护一套独立**行业**；
- 按**行业**维护**研究员**归属，支持**同一行业多个研究员**；
- 支持**一个研究员跨多个行业、跨多个市场**（多对多）。

不在本模块范围：行业下挂哪些股票（→ ③）、研报内容（→ ⑤）。

---

## 2. 数据结构

### 2.1 核心模型

```
市场 (Market)             可配置：香港 / 美国 / 日本 / 韩国 / ...
  └─ 行业 (Industry)       每个市场下一套独立行业（同名行业在不同市场是不同记录）
       │
       └─< 行业-研究员关系 >─┐   多对多，可跨市场
                            │
研究员 (Analyst)  <──────────┘   = ① 的"研究员"角色用户 + 专业属性（1:1 绑账号）
```

### 2.2 实体字段

#### 市场 (Market)

| 字段 | 说明 | 备注 |
| --- | --- | --- |
| 市场代码 | 如 `HK` / `US` / `JP` / `KR` | 唯一，稳定不改 |
| 市场名称 | 香港 / 美国 / 日本 / 韩国 | |
| 排序 | 列表展示顺序 | |
| 状态 | 启用 / 停用 | 停用后不出现于研报/组合的市场筛选 |

#### 行业 (Industry)

| 字段 | 说明 | 备注 |
| --- | --- | --- |
| 所属市场 | 外键 → 市场 | 一个行业必属一个市场 |
| 行业代码 | 市场内唯一 | 如香港·地产 = `HK-RE` |
| 行业名称 | 地产 / 金融 / 科技 | 同名在不同市场是不同记录 |
| 排序 | 该市场内顺序 | |
| 状态 | 启用 / 停用 | |

> ⚠️ 行业强绑市场。"金融"在香港和美国是两条独立记录，各自挂研究员、各自被研报引用。

#### 研究员 (Analyst)

研究员 = 系统用户里带"研究员"角色的，**1:1 关联账号**（来自 ①）。专业属性在本模块维护：

| 字段 | 说明 | 备注 |
| --- | --- | --- |
| 关联账号 | 外键 → 用户（①） | 1:1，该用户须含"研究员"角色 |
| 研究方向 | 文本，自由描述 | 如"港股大消费" |
| 所属行业（多） | 多对多关系 → 行业 | 见下，可跨市场 |
| 状态 | 在职 / 离职 | 软状态 |
| 入职/备注 | — | |

> 研究员的账号、姓名、邮箱、部门等**不在本表重复存储**，来自 ① 的用户表；本表只放专业属性。

#### 行业-研究员关系（多对多）

| 字段 | 说明 |
| --- | --- |
| 行业 | 外键 → 行业 |
| 研究员 | 外键 → 研究员 |
| 关系类型 | 主覆盖 / 协助（可选，先留字段） |

**多对多含义：**
- 一个行业挂多个研究员（覆盖同一行业的多人团队）；
- 一个研究员挂多个行业（资深/组长跨行业）；
- 一个研究员可跨市场（如张三 = 香港·地产 + 美国·半导体）。

## 3. 权限衔接（来自 ①）

| 权限点 | 能做什么 | 默认归属 |
| --- | --- | --- |
| `行业增删` | 增删**市场**与**行业本身** | 管理员（可授权给研究员角色或某用户） |
| `改行业研究员名单` | 维护"哪个研究员挂在哪个行业"的**关系** | 研究员 |

> 关键边界：未授 `行业增删` 的研究员，只能改行业下挂的**研究员名单**，不能新增/删除行业和市场本身。这是 ① 已定义的两个独立权限点，本模块严格执行。

### 3.1 数据层权限（行级范围）

补全 ① 留待本模块的数据层权限：

- 研究员查看"本行业数据"的边界 = 该研究员通过关系表挂载的所有行业（可跨市场）。
- 例：张三挂 香港·地产 + 美国·半导体 → 他能看这两个行业的研报、股票池；看不到其他行业。
- 拥有 `查看全部研报` 等强权限点者，不受行业范围限制。

## 4. 页面与交互

### 4.1 三级联动浏览

推荐"市场 → 行业 → 研究员"三级联动界面：

- **顶部/左侧**：市场分段控件（全部 + 各市场）；"全部"视图聚合所有市场的行业，行首以"市场 · 行业"格式标识来源；
- **中间**：该市场下的行业列表（表格），显示行业名称、研究员 chips（在职绿色/离职灰色，主覆盖/协助标识）、状态；
- **右侧/下方**：该行业挂载的研究员名单（可增删）。

> 原型实现：左侧行业列表每行显示"市场 · 行业"（不换行）、研究员姓名 chips（多行换行），末尾有"编辑"/"删除"操作按钮。

### 4.2 操作分布

| 操作 | 所需权限点 | 入口 |
| --- | --- | --- |
| 新增/编辑/删除市场 | `行业增删` | 市场列表 |
| 新增/编辑/删除行业 | `行业增删` | 行业列表（含编辑/删除按钮，删除时二次确认） |
| 行业下增删研究员（维护关系） | `改行业研究员名单` | 研究员名单区 |
| 编辑研究员专业属性 | `改行业研究员名单` | 研究员详情 |

无权限的操作按钮按 VP 规范的"操作层"控制——直接隐藏，不灰显。

### 4.3 VP UI 要点

- 遵循 [`docs/design/ui-spec.md`](../design/ui-spec.md)。
- 市场切换用货币分段控件风格（5.6）：`#E8F3EC` 外层底，激活项白底 + `#0A3726` 文字。
- 行业/研究员名单用标准数据表格（14px 正文、12px `#EFF5F1` 表头、`#F2F8F4` 偶数行、hover `#E8F3EC`）。
- 研究员多对多挂载：在一个行业下"添加研究员"用多选搜索下拉（搜账号/姓名）。
- 行业列表研究元展示：每行以 chips 标签展示该行业全部研究员（在职=绿色标签，离职=灰色标签，主覆盖不加标识，协助者标注"·协助"后缀），支持多行换行。
- "全部市场"视图：聚合所有市场行业，行首以"市场 · 行业"格式标识，行业名列不换行。
- 删除行业/市场须二次确认弹窗；已挂研究员或被研报引用时，按软删除处理并提示。

---

## 5. 关键规则与约束

- **市场、行业、关系均为软删除/停用**：停用后不在筛选器出现，但历史研报/组合的引用不断裂。
- **行业强绑市场**，不存在"跨市场的同一行业"实体，只有各自独立的同名记录。
- **关系可重叠**：同一研究员在不同行业可有"主覆盖/协助"等多种关系，互不冲突。
- **研究员离职**：置为离职态、停用其账号（① 的用户停用），保留关系记录用于历史溯源；不物理删除。
- 研究员**必须先在 ① 有账号且含"研究员"角色**，才能在本模块被挂到行业。
